# MEDIA_CAPABILITIES — قدرات الفيديو والصوت والحجب

تاريخ: 2026-10-21. **تحذير صريح:** لم يُشغَّل التطبيق على أي جهاز أو محاكٍ (لا KVM ولا macOS في بيئة التطوير، انظر
ENVIRONMENT.md). كل ما في عمود «الحالة» مبني على: قراءة كود المحرك والمكتبة، البناء الناجح، واختبارات Chromium
سطح مكتب بمحاكاة جوال. أي سطر «لم يُجرَّب على جهاز» يجب التحقق منه قبل الإعلان عن الميزة.

مفتاح الحالة: **منفّذ** = الكود موجود ويُبنى · **مختبر-جهاز** = جُرّب على جهاز حقيقي (لا يوجد حالياً) ·
**غير مدعوم** = لن يعمل بهذه البنية · **يعتمد على الموقع** = سلوك الموقع يقرر.

> **سياسة YouTube المبرمجة:** على نطاقات `youtube.com` و`youtu.be` و`youtube-nocookie.com` يوقف التطبيق التشغيل عند
> الانتقال للخلفية ولا يدخل PiP تلقائياً ولا يعرض زر PiP، مهما كانت إعدادات المستخدم
> (`mobile/lib/media/media_policy.dart`)، لأن التشغيل بالخلفية ميزة مدفوعة في شروط YouTube ولأن سياسة Google Play
> تعتبر تمكينه مخالفة. القائمة مضمّنة وليست قابلة للتغيير عن بعد.

## 1. Android (Android System WebView عبر flutter_inappwebview 6.1.5)

| الميزة | الحالة | كيف | القيود والسبب |
|---|---|---|---|
| تشغيل الفيديو داخل الصفحة | منفّذ، لم يُجرَّب على جهاز | WebView القياسي، `mediaPlaybackRequiresUserGesture: true` | التشغيل التلقائي بصوت يحتاج لمسة المستخدم (لتوفير البيانات وعدم الإزعاج). |
| ملء الشاشة | منفّذ، لم يُجرَّب | `onEnterFullscreen/onExitFullscreen` ← إخفاء الأشرطة + `immersiveSticky` | يعتمد على استدعاء الموقع لـ Fullscreen API. |
| تدوير الشاشة | منفّذ، لم يُجرَّب | في ملء الشاشة نسمح بكل الاتجاهات، وخارجه نعود للافتراضي | |
| Picture-in-Picture | منفّذ (Native)، لم يُجرَّب | `MainActivity` قناة `vela/pip`: PiP للنشاط كاملاً مع `setAutoEnterEnabled` (Android 12+) أو `onUserLeaveHint` (8–11)، فقط أثناء فيديو بملء الشاشة وإذا فعّله المستخدم؛ الواجهة تعرض الـ WebView فقط داخل PiP | Web PiP API (`requestPictureInPicture`) **غير مدعوم** في Android WebView. أجهزة/مشغلات تمنع PiP ترجع false. |
| الصوت بالخلفية (التطبيق في الخلفية) | منفّذ جزئياً، لم يُجرَّب | المكتبة لا توقف WebView تلقائياً؛ إذا عطّل المستخدم «متابعة الصوت» نستدعي `pause()` | (أ) Chromium يجعل الصفحة `hidden` عند إخفاء النافذة، ومواقع كثيرة (منها YouTube للمستخدم غير المشترك) **توقف التشغيل بنفسها** — لا نتحايل على ذلك ولا نزوّر Page Visibility. (ب) بدون Foreground Service من نوع `mediaPlayback` قد يقتل النظام العملية بعد دقائق. لم نضف خدمة مقدّمة لأنها تتطلب ربطاً صحيحاً بحالة التشغيل الفعلية وإعلاناً في Play Console؛ مؤجلة (انظر HANDOFF). |
| مع قفل الشاشة | نفس السطر السابق | | نفس القيود. |
| أزرار التحكم في شاشة القفل / MediaSession | **غير منفّذ** | | Android WebView لا يربط `navigator.mediaSession` بـ MediaSession النظام (Chrome يفعل). يتطلب جسراً + خدمة؛ مؤجل. |
| المكالمات / فصل السماعات / تغيير مصدر الصوت | يعتمد على WebView | WebView يطلب Audio Focus بنفسه عند التشغيل | لم نضف معالجة خاصة؛ لم يُجرَّب. |
| تعارض تشغيل تبويبين | جزئي | تبويب واحد فقط مرئي؛ التبويبات المخفية تبقى حية (keep-alive) وقد تتابع الصوت؛ التجميد لا يقتل تبويباً يشغّل وسائط | لا «إيقاف تلقائي للتبويب الآخر» بعد. |
| DRM (Widevine) | يعتمد على الموقع/الجهاز | `PROTECTED_MEDIA_ID` **مرفوض** حالياً في `onPermissionRequest` | لا نتجاوز DRM أو الاشتراكات. محتوى DRM لن يعمل حتى نضيف موافقة صريحة لذلك. |
| تنزيل فيديو المواقع | **غير مدعوم عمداً** | نحفظ فقط ما يقدّمه الموقع كتنزيل مباشر (`onDownloadStartRequest`) | لا استخراج تدفقات ولا تحويل لصوت. |

## 2. iOS (WKWebView عبر flutter_inappwebview 6.1.5) — **لم يُبنَ ولم يُختبر**

| الميزة | الحالة | كيف | القيود |
|---|---|---|---|
| تشغيل داخل الصفحة | منفّذ | `allowsInlineMediaPlayback: true` | |
| ملء الشاشة + تدوير | منفّذ | مشغل iOS الأصلي يتولى ملء الشاشة والتدوير | |
| Picture-in-Picture | منفّذ (إعداد) | `allowsPictureInPictureMediaPlayback: true` ← زر PiP في مشغل النظام | يعمل فقط حيث يسمح المشغل؛ المواقع التي تستخدم مشغلاً مخصصاً قد تخفيه. |
| الصوت بالخلفية | منفّذ (إعداد) | `UIBackgroundModes=audio` + `AVAudioSession.playback` في `AppDelegate` | WebKit يوقف **الفيديو** عادة عند الخروج؛ الصوت قد يستمر. مواقع كثيرة توقف بنفسها. يحتاج تبريراً في App Review (التطبيق يشغّل صوتاً مسموعاً). |
| شاشة القفل / Now Playing | يعتمد على WebKit | WebKit يدعم Media Session في iOS 15+ لبعض الحالات | لم يُجرَّب. |
| المكالمات/السماعات | يتولاها AVAudioSession/WebKit | | لم يُجرَّب. |

## 3. حجب المحتوى

| البند | Android | iOS |
|---|---|---|
| الآلية | اعتراض الطلبات داخل flutter_inappwebview (`shouldInterceptRequest` + regex Java) | `WKContentRuleList` مُترجم من نفس القواعد |
| القواعد الشبكية (`block`) | منفّذ | منفّذ |
| القواعد التجميلية | سكربت `vela-cosmetic` موحّد (نفس الكود) | نفسه |
| الاستثناء لكل موقع | بتبديل `contentBlockers` للـ WebView عند التنقل + السكربت يتجاهل المواقع المستثناة | نفسه |
| عداد المحجوب | **غير معروض** (لا يمكن القياس الدقيق على iOS) | **غير معروض** |
| الأداء | regex خطي لكل طلب؛ الحد 5000 قاعدة، القائمة الحالية 50 قاعدة شبكية | يُترجم مرة عند تغيير القائمة |
| الحجب خارج المتصفح | غير موجود (لا VPN، لا شهادات) | غير موجود |

**الاستنتاج الصريح عن YouTube:** إعلانات الفيديو داخل YouTube تُقدَّم من نطاقات YouTube/Google نفسها (نفس نطاق المحتوى)،
لذلك **قائمة الحجب بالنطاقات لا توقفها**، وحجبها يتطلب منطقاً خاصاً بالموقع يخالف شروط YouTube ويتغير باستمرار.
لا نعد بـ «YouTube بلا إعلانات». ما تفعله القائمة: تقليل إعلانات وتتبّع الأطراف الثالثة في المواقع العامة.

## 4. ما يجب تجربته على جهاز (صفحات `test-pages/`)

`python3 test-pages/serve.py` ثم `adb reverse tcp:8765 tcp:8765` وافتح `http://localhost:8765/media.html`:
تشغيل، ملء شاشة، تدوير، PiP (الخروج أثناء ملء الشاشة)، قفل الشاشة، مكالمة واردة، فصل سماعة، تبويبان بصوت.
وعلى المواقع الحقيقية (بحساب اختبار، لا حسابات شخصية): YouTube، Twitch، TikTok، Rumble، موقع عام. سجّل في TEST_REPORT.md.
